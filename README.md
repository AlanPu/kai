# 英语口语陪练

一个自己用的英语口语练习工具。给一个主题、一段话、一篇文章或一个网址，
它会先"备课"——分析材料、规划几个话题——然后和你一对一练口语。

不是背单词软件，也不是题库。它更像一个**有准备的陪练**：
知道今天聊什么、记得你上次说过什么、会纠正你反复犯的错，
但**尽量多让你说**。

---

## 它是什么样子

练一次大概这样：

1. 粘一段材料进去（比如一篇讲远程办公的英文文章）
2. 它分析完，给出几个准备聊的话题
3. 开练。**按住空格说话，松开表示说完了**
4. 它一边聊一边记：你的兴趣、背景、反复出错的表达
5. 说错了它会纠正，但不会频繁打断
6. 你卡住不说话，过一会儿它会主动换个角度提问

一次 30 分钟，一周两三次。

---

## 快速开始

```bash
cd kai
cp .env.example .env        # 填 DASHSCOPE_API_KEY 和 QWEN_WORKSPACE_ID
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/check_qwen.py   # 自检：确认密钥/模型能用（几乎零成本）
./start.sh
```

浏览器打开 `http://127.0.0.1:8000`。

**第一次用会引导你录入声纹**（跟读 5 句话），这样它能"只回应你的声音"，
不会被旁人说话或外放的声音打断。多人共用一台电脑时，每人一套声纹、
画像和练习记录，互不干扰。

> 完整搭建步骤（含声纹模型下载、手机访问、常见问题）见 **[SETUP.md](SETUP.md)**。

## 几个设计上的选择

这些地方和"常规做法"不太一样，都是有原因的：

### 按住空格说话，而不是自动判断

早期版本用 VAD 自动断句，但实际用起来很难受：停顿想词的时候会被
判成"说完了"，环境噪音也会误触发。改成**按住空格说话、松开表示说完**，
控制权完全在用户手里。

不按空格时麦克风不采集 —— 这一点是刻意的。

### 冷场时会主动找话题（15 秒，可配置）

因为回合完全由用户发起，用户不开口 AI 就永远不说话。安静本身没错，
但卡住想不出句子时会一直干等。所以超过 15 秒没动静，AI 会换个角度
问一句。**最多连续问 6 次**，之后安静等你 —— 避免自说自话。

阈值和次数都在 `.env` 里改（`IDLE_NUDGE_SEC` / `IDLE_NUDGE_MAX`），
设 `IDLE_NUDGE_MAX=0` 就是关掉。

### 发音只纠"明显错误"

逐音素纠音会打断表达流畅度，得不偿失。所以只纠**明显**的发音问题，
而且不会一听到就打断。

### 语音模型和文本模型是两件事

- **语音模型**（Qwen Realtime）负责"听懂并回话"
- **文本模型**负责备课、语法纠错、总结学习画像

两者共用同一个 API Key，但**作用不同**：文本模型挂了仍然能对话，
只是"生成话题"会失败。都能在 `.env` 里自己换（见 SETUP.md）。

### 模型、音色、节奏全部可配置

没有哪一项是写死在代码里的。启动时会打印实际生效的配置：

```
模型配置：
  语音对话  qwen3.5-omni-flash-realtime-2026-03-15
  语音转写  qwen3-asr-flash-realtime
  文本（材料准备/纠错）  qwen-plus
  文本接口  https://dashscope.aliyuncs.com/compatible-mode/v1
  冷场等待  15 秒（最多主动开口 6 次）
```

**音色可以在网页上实时切换**：点右上角「音色」，每个可试听的音色
都有 ▶ 按钮，听完再选。

## 项目结构

```
kai/
├── start.sh              启动脚本（先停旧进程、健康检查、打印生效配置）
├── run.py                入口（等价于 python -m app）
├── app/
│   ├── api/server.py     HTTP + WebSocket 服务
│   ├── core/             配置、实时语音、声纹、内容抓取、音色清单
│   ├── services/         备课、纠错、学习画像、成本估算
│   ├── storage/          SQLite 存储
│   └── web/index.html    前端（单文件，无构建步骤）
├── scripts/              自检、证书生成、音色列表等工具
├── tests/                278 个测试
├── docs/                 使用说明、开发计划、诊断记录、选型分析
└── prototype/            原型期代码（已冻结，仅作对照）
```

分层是**测试强制**的：`core` 不能 import `services`，
`services` 不能 import `api`。违反会直接测挂。

## 已知限制

诚实列一下，免得期待过高：

- **声纹不是安全级别的**。它用于过滤旁人说话，不能当身份认证。
  刚开始的一两秒可能有一次误判（多数表决窗口还没填满）。
- **换麦克风或环境变化后准确率会下降**，感冒鼻音重时也会。
  可以随时重新录入。
- **音色有 17 个可选，但只有 6 个能在线试听** —— 音色有两套清单
  （对话模型一套、语音合成一套），只有部分重叠。其余的要点官方的
  [音色列表](https://help.aliyun.com/zh/model-studio/omni-voice-list)试听。
- **费用是估算值**，实际以阿里云账单为准。
- **手机浏览器没实测过**。HTTPS 和局域网访问验证过，但没有真机跑过。

## 依赖

Python 3.14。主要依赖：FastAPI + uvicorn、websockets、numpy、
sherpa-onnx（声纹，不依赖 PyTorch）。

语音和文本用的是阿里云百炼（DashScope）。国内服务直连即可，
不需要代理。

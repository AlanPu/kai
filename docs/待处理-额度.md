## 顺带说：这个意外帮忙找出了三个真实缺陷

额度耗尽的错误帧长这样（注意**没有 type 字段**）：

```json
{"code": "AllocationQuota.FreeTierOnly", "message": "..."}
```

服务端发完它就掐断连接。我的解析只看 `type`，于是：

1. **整条错误被跳过** —— 用户看到「莫名其妙就结束了」，
   真正原因一个字都没显示
2. **致命信号被自己的异常处理吞掉** —— 识别出来了，
   但 `SessionFatal` 穿不过通用 `except`，降级成一条 warning
3. **接收任务是 fire-and-forget** —— 异常只存在 task 对象里，
   永远没人发现。连接死了上层完全不知道，会话一直挂着发 tick

第 3 条很可能就是之前那次「报错后空转 24 分钟」的真正原因 ——
我当时以为是没识别出错误，其实识别了，只是信号传不出去。

三个都已修复并加了回归测试。这类问题只有「连接以不寻常的
方式死掉」时才会显形，常规测试和 30 分钟 soak 都碰不到。

**现在额度耗尽时会明确告诉你去哪儿解决，并正常给出报告。**

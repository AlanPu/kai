## 1. 需求（确认版）

| # | 需求 | 落实方式 |
|---|---|---|
| 1 | 输入：主题 / 段落 / 文章 / 网址 | 统一走「内容分析 → 生成话题计划」 |
| 2 | 主动引导我说，但要**多给我说的机会** | 引导语简短，AI 说话占比目标 ≤ 40% |
| 3 | 语法纠错 + 地道表达建议 | 界面实时显示，不打断 |
| 4 | 发音：明显单词错误才纠正 | 分级判定，口音问题默认不纠 |
| 5 | 角色：陪练 / 一对一辅导老师 | 写进系统提示词 |
| 6 | 历史记录 + 个性化 | SQLite + Markdown 个人画像 |

### 已确认的关键决策

- **存储**：SQLite（会话/统计数据）+ Markdown（个人画像，可读可改）
- **纠错时机**：界面实时显示 + 语音里自然带一句（**不打断**）
- **时长**：约 30 分钟，到点自动结束并生成报告
- **推进**：分阶段，每阶段可运行可验收

### ⚠️ 需求冲突及解决

原选择「语音实时纠正」与「多给我说的机会」「不要频繁打断」直接矛盾。
**已解决**：AI 不插话；纠错显示在侧栏，并允许 AI 在**你说完一段后**自然地
把正确说法嵌进回应里，例如：

> "Oh, you went to the park? Nice — by the way, we say *I went*, not *I go*."

这样既实时又不打断。

## 2. 架构

```
┌──────────────────────────────────────────────┐
│  浏览器 (app/web)                             │
│  录音 / 播放 / 侧栏纠错 / 历史 / 报告          │
└────────────────┬─────────────────────────────┘
                 │ WebSocket（音频 + 事件）
┌────────────────▼─────────────────────────────┐
│  FastAPI (app/api)                           │
│  · /ws  实时对话通道                          │
│  · /api/sessions  历史与报告                  │
│  · /api/profile   个人画像                    │
└────────────────┬─────────────────────────────┘
                 │
     ┌───────────┼───────────┬──────────────┐
     ▼           ▼           ▼              ▼
┌─────────┐ ┌─────────┐ ┌─────────┐ ┌──────────┐
│ Realtime│ │ 话题规划 │ │ 纠错分析 │ │ 个人画像  │
│  会话    │ │ planner │ │ correct │ │ profile  │
└─────────┘ └─────────┘ └─────────┘ └──────────┘
     │           │           │              │
     ▼           ▼           ▼              ▼
  Qwen WS    LLM(文本)   LLM(文本)     SQLite+MD
```

**要点**：实时语音走 Qwen Realtime（低延迟）；
话题分析/纠错/画像抽取走**普通文本 LLM**（便宜、可控、可重试）。

## 6. 风险

| 风险 | 应对 |
|---|---|
| 30 分钟长连接断开 | 阶段 6 做重连 + 上下文恢复 |
| 纠错延迟高，体验差 | 纠错**异步**进行，不阻塞对话 |
| 实时纠错 API 调用费 | 按句批量提交，不逐字调用 |
| 个人画像越写越乱 | Markdown 结构固定，只允许追加/覆盖指定节 |
| 音频计费不可控 | 阶段 6 加费用统计与上限告警 |
